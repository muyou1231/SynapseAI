## 二、项目描述（150 字，放在职责前）

> 面向「把众多 AI 工具连接在一起」的目标，从零设计并实现的全栈 AI 能力集成平台。以即时通讯为底座，包含用户体系、好友/群聊、实时消息、AI 助手、学习空间、朋友圈审核、语音通话与管理后台；自研 MCP 功能框架将 AI 能力做成可配置、可热启停的插件式模块。后端 1.3 万行代码、160 个 REST 接口、28 张业务表，前端零构建、原生 JS 模块化约 1.5 万行。

## 三、核心职责（四选一，别全塞）

### A. Java 后端方向（推荐，6 条）

- **架构设计**：基于 Spring Boot 3 + Java 17 从零搭建全栈平台，划分 18 个业务模块、160 个 REST 接口、28 张数据表；采用 Controller-Service-Mapper 三层架构与统一返回体，Mapper 层全部显式编写 SQL 注解而不依赖 ORM 继承，使复杂查询与索引优化完全可控。
- **实时通信**：设计 REST + WebSocket(STOMP/SockJS) 双通道通信架构，在握手阶段解析 Token 并绑定 Principal，业务侧拒绝信任报文中的发送者身份，从源头杜绝身份伪造；抽象单播 / 群播 / 私有会话三类 Topic 分发消息，配合自增 ID 增量补拉与指数退避重连（1s→15s），实现断线后消息零丢失、零重复。
- **消息可靠性**：在消息发送链路上前置裁决冻结、拉黑、限流与解散状态，非法消息不落库不转发并在同一连接回推错误；消息搜索在 SQL 层使用 `EXISTS` 子查询校验群成员身份，防止越权读取他人会话。
- **AI 能力集成**：基于 openai-java SDK 对接阿里云百炼 OpenAI 兼容协议，使用 `SseEmitter` 输出流式结果实现打字机效果；针对推理模型思考链污染结构化输出的问题，通过请求参数关闭思考过程保障 JSON 解析稳定；学习空间按会话子线隔离多轮上下文，流式过程中逐 token 回写数据库，页面刷新可恢复未生成完的回复。
- **MCP 可插拔框架**：设计配置驱动的 AI 能力框架，能力以配置行持久化（唯一编码、开关、JSON 参数），管理端可热启停，前端按已启用能力动态渲染入口；内置消息群发助手实现「自然语言 → AI 结构化 JSON → 收件人四类解析 → 去重预览 → 批量落库推送」的 Agent 化链路，单批上限 50 人并排除自发送。
- **数据与安全**：针对 MySQL 5.7 不支持 `IF EXISTS` 的限制，设计「存储过程 + 异常吞没」的幂等迁移模板，25 个增量脚本可重复执行、不覆盖线上数据；按查询模式设计 66 个索引（群聊历史联合索引、炸弹到期扫描索引等）；引入 Redis 分级缓存并配置降级回源，缓存故障时自动回源数据库不阻断业务；时间胶囊正文采用 AES-256-GCM 加密存储（随机 12 字节 IV 随密文保存），到期前服务端不下发任何明文与密文。

### B. AI 应用 / Agent 方向（推荐，6 条）

- 基于 openai-java SDK 对接大模型 OpenAI 兼容接口，实现同步与流式两种调用模式，使用 `SseEmitter` 将流式结果实时推送到前端形成打字机效果，并通过独立线程池与超时控制避免阻塞请求线程。
- 针对推理模型会输出思考链、污染结构化结果的问题，通过请求参数关闭思考过程，配合首尾截取与 `asText()` 取值，稳定解析 AI 返回的业务 JSON。
- 自研 MCP 可插拔 AI 能力框架：能力以配置行持久化（唯一编码、开关、JSON 参数），管理端可热启停，前端按已启用能力动态渲染入口，新能力接入无需改动前后端代码。
- 实现消息群发助手：自然语言指令经 AI 解析为结构化 JSON，再经收件人四类解析（账号 / 昵称 / UID / 关键词模糊展开）、去重、预览确认后批量落库并 WebSocket 推送，单批上限 50 人，形成完整的 Agent 化执行链路。
- 构建 AI 账号体系：启动时自举 `role=AI` 的助手账户并自动建立好友关系，支持为每个助手配置独立人设 Prompt，AI 状态变更通过 WebSocket 实时广播。
- 设计 AI 内容审核与降级机制：朋友圈内容先经 AI 审核，判定失败转入人工复核状态机；AI 服务异常时降级放行转人工，保证用户发布链路不被阻塞。

### C. 全栈方向（6 条）

- 后端基于 Spring Boot 3 + Java 17，前端零构建，14 个原生 JavaScript 模块按职责划分（消息 / 好友 / 群聊 / 朋友圈 / 通话 / 学习 / 绘画 / MCP），以命名空间挂载，无打包构建步骤。
- 设计 REST + WebSocket 双通道通信：握手阶段绑定身份，按单播 / 群播 / 私有会话三类 Topic 分发；前端实现指数退避重连（1s→15s）与 visibilitychange 立即重连，重连后按自增 ID 增量补拉离线消息。
- 使用 fetch + `ReadableStream` 自行解析 SSE 分帧实现 AI 打字机（原生 EventSource 无法携带自定义鉴权头），支持 `AbortController` 中断生成。
- 语音通话基于 WebRTC `RTCPeerConnection` 点对点传输，服务端仅中继 OFFER / ANSWER / ICE 信令并强制使��握手身份，防止信令冒用。
- 消息 UI 采用乐观插入 + `data-mid` 判重 + 回执替换，保证弱网与重连场景下不出现重复气泡。
- 后端实现 160 个 REST 接口、28 张数据表与 66 个索引，Mapper 层显式编写 SQL 注解，关键查询使用相关子查询一次带出评论数与点赞数，避免 N+1。

### D. 精简版（一页简历空间紧张时用，4 条）

- 从零设计并实现全栈 AI 能力集成平台，后端 1.3 万行代码、160 个 REST 接口、28 张业务表，前端原生 JS 约 1.5 万行。
- 设计 REST + WebSocket(STOMP) 双通道实时通信架构，握手阶段绑定身份防伪造，结合自增 ID 增量补拉与指数退避重连，实现断线消息零丢失。
- 自研 MCP 可插拔 AI 能力框架，实现自然语言 → 结构化 JSON → 业务执行的 Agent 化链路，管理端可热启停。
- 基于 SSE 实现 AI 流式输出；时间胶囊采用 AES-256-GCM 加密存储；设计 MySQL 5.7 幂等迁移模板与 66 个索引，Redis 缓存支持故障降级回源。

## 四、可以适度拔高的表述（口径可控）

以下说法在面试中**可以讲**，因为背后有真实实现支撑，只是表述更凝练：

| 简历写法 | 实际支撑 |
|---|---|
| 「从源头杜绝身份伪造」 | 业务侧取 `Principal`，不读报文 senderId |
| 「消息零丢失、零重复」 | 自增 ID 补拉 + 前端 `data-mid` 判重 |
| 「完全可控可优化」 | Mapper 全显式 SQL，不用 BaseMapper |
| 「不阻断业务」 | `CacheErrorHandler` 降级回源 |
| 「Agent 化链路」 | NL → JSON → 解析 → 去重 → 预览 → 批量执行 |
| 「密态存储」 | AES-256-GCM，到期前连密文都不下发 |
